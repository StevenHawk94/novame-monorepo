# Burrow 资金与数据安全加固交付

范围：接续 [只读安全审计](security-audit-2026-10-24.md)，按用户确认实施。批准包括移除 Airwallex、自动 Sandbox 经济域隔离、固定经济日历，以及验证后上线 API/迁移；不包括清空钱包、撤销现有订阅、删除历史订单或发布 App。

## 核心修复

| 风险 | 权威边界与修复 |
| --- | --- |
| 旧 Apple 收据重新授予会员 | Apple 官方签名库验证 App/环境/账号，查询官方当前交易与订阅状态后结算；历史签名不直接代表当前权益，不补造有效期 |
| 订阅状态被客户端标签控制 | Profile tier 仅是投影；API/经济 RPC 共用有效订阅与当前互相配对、同经济域的权益判断；生产 dev-tier 通道关闭 |
| 测试权益流入真实账号 | 经官方确认后自动固定测试域；真实付费历史不能转入测试域，测试账号不能再用于真实付费；跨域付费赠礼、Surprise、付费游戏和 Plus 共享受服务端及事务回滚保护 |
| Google 已入账却报消费失败 | 发币和 durable consume 任务原子保存；consume/acknowledge 后台幂等重试，已确认到账不因收尾或刷新失败被改成失败 |
| 重放、乱序、重复扣款/发币 | 凭据与 App 账号绑定；删除后保留占用 tombstone；官方当前状态、事件版本、原幂等键及数据库一致锁顺序共同保护 |
| 改时区重复领每日奖励 | 迁移固定既有账号经济时区，新账号首次经济使用固定；每日奖励/配额从同一时区算日期，之后改资料/设备时区不增加次数 |
| 任意上传头像/伪造图片 | 关闭公共 INSERT，签名票据、归属及限流，服务端真实解码、尺寸/体积限制、去元数据及重新编码 |
| 旧会话或误触删除账号 | 在线用户及活跃会话检查；已绑定账号通过已确认邮箱验证码，匿名账号保留两次明确确认；部分删除失败不报成功，支持安全重试 |
| 废弃 Airwallex 支付面 | 四个遗留支付/回调入口返回 410，不解析请求、不修改订单；移除客户端入口实现，历史记录保留 |
| 高频请求/安全依赖故障 | 关键经济、上传及删除接口按用户与 IP 限流，关键检查故障安全拒绝；普通页面打开不增加商店核验或敏感会话联网 |

迁移 269–272 均为本轮安全边界。固定经济时区不改变 Memories 的共同日历、日记历史或换页规则；不改变 Free/Plus 数值、奖励金额、个人房间与库存归属、通知准备后再提醒的原则。

## 支付失败的正确含义

- 商店拒绝、支付失败、待批准或无有效购买凭据：不新授予会员/金币。
- 商店已扣款、服务器暂时核验失败：保留同一订单重试/恢复，不当作未扣款，不重复发起付款；不能直接承诺自动银行退款。
- 已服务端提交入账：保持成功；StoreKit finish、Google consume/acknowledge、缓存或 UI 异常不反转该事实。
- 官方确认退款/撤销：按权威状态幂等对账；现金退款走 Apple/Google 官方流程。
- 订阅历史冲突不占住独立金币恢复队列；取消金币购买仍静默返回原弹窗。

## 兼容与上线

实际生产版本、迁移校验、数据保护与验证时间以 [机器可读交付记录](../tools/reports/security-hardening-2026-10-24.json) 为准。发布只使用已核对生产基线加明确安全文件，不直接部署脏工作区；Admin、公告和强更配置不变。

客户端账号删除验证码及经济时区用途分离需随新版 App 发布。旧删除请求缺少确认挑战时安全拒绝，不降级回仅凭 JWT 删除。旧客户端 bootstrap 将返回的资料时区投影为固定经济时区，兼容每日领取；不修改真实资料。新版通过 `X-Burrow-Economy: 1` 保留资料时区用于当地展示，单独使用 `economicTimezone` 做配额判断。

新测试账号无需名单，但测试配对双方均需通过真实 Sandbox 凭据确认测试域；一个未测试的新账号默认 production，不随伙伴自动转域。已属于测试域的账号请勿用于真实付款，应另用真实账号。过去未知商店环境的历史订阅不凭猜测改域或撤销；在恢复/当前核验时确认。历史隔离钱包不回填真实钱包。

## 验证范围

- `pnpm test:domain-isolation`：592 项通过，0 失败，含支付隔离、取消、通知就绪、房间/素材边界及主要生命周期合同。
- 支付/头像/删除/固定经济日期专项：60 项通过，0 失败；含官方 Apple 验签拒绝伪造 JWS、真实图片解码、真实 JWT 密码学验证。
- 隔离 PostgreSQL 安全测试：15 项通过；分别使用仓库组合及已部署函数的无用户数据 schema 定义验证，覆盖回执重放/乱序、域隔离、领取幂等、时区跳变、删除挑战、租约和客户端权限。修改经济日历时，不相关函数定义与权限逐项保持一致。
- 个人房间迁移及 Memories 迁移专项均通过；生产迁移另设 22 类既有数据行摘要保护及不相关函数/权限保护。
- 移动端 TypeScript、领域边界检查、最终 Vercel 生产候选构建通过。Apple Production/Sandbox 官方接口均通过配置鉴权预检；使用合成的不存在交易查询，不产生购买或改订阅。
- 候选 Google 回调匿名请求返回 401，确认运行时已开启身份鉴权；不是仅凭环境变量名字存在推断安全。
- 上线探测曾发现头像函数缺少 Sharp 的 libvips 共享库，已补齐该路由专用的 monorepo 文件追踪，并增加构建后的二进制/共享库存在性及实际编解码门禁。Linux 云端构建通过后再复测接口、发布修订；不会通过移除真实解码来绕过安全检查。

## 不能夸大的边界与运维事项

- 有限测试不是“绝无漏洞”证明。没有进行真实扣款/退款、真实 Google Pub/Sub 身份推送、完整 Sandbox 双机支付、真实邮箱投递或所有设备重新采样 FPS；本轮没有新增页面点击联网、全局 UI 监听或原生依赖。
- 普通 JWT 使用本地签名与时效校验，退出/撤销至自然到期仍有窗口；删除使用额外在线活跃会话检查。匿名账号没有独立身份凭据，不能宣称与邮箱二次确认同等级。
- 商店 webhook 为主要实时来源，后台 cron 为漏通知兜底；需持续监控队列最老待处理时间、失败率、Apple/Google 服务可用性及 Google 确认期限。当前有界任务批量不是无限吞吐保证，规模增大时应压测并扩容 worker，不把任务塞回用户点击主链。
- 旧版兼容不等于所有历史权益都已重新向商店核查。已存在的有效历史订阅不在部署时批量撤销；确认到新状态后统一按新权威快照判断。
- 本轮未验证云账户 MFA、外部 WAF、密钥轮换、数据库 PITR/备份恢复演练。废弃 Airwallex 外部账户密钥应在供应商后台另行撤销；代码不再引用不代表外部密钥自动失效。
- 发布回退不得重新打开旧的“仅历史收据即授予权益”或公共写权限。保留不可逆经济账本与新 schema，使用安全兼容 API/前向修复；不要通过回滚迁移、清空凭据或余额解决异常。

开发基线已同步更新为 [v1.6](burrow-development-standards.md)。后续变更仍需用户明确批准才能改这些业务边界。

## 对照的官方规则

- [Apple 当前订阅状态查询](https://developer.apple.com/documentation/appstoreserverapi/get-all-subscription-statuses) 与 [Apple 官方 Node 验签库](https://github.com/apple/app-store-server-library-node)：签名校验和当前状态核验分开，历史收据不直接授权。
- [Google Play Billing 购买生命周期](https://developer.android.com/google/play/billing/integrate)：先核验、再授予、再确认/消费；待支付不授予权益，取消订阅与到期不是同一状态。
- [Supabase 会话规则](https://supabase.com/docs/guides/auth/sessions)：敏感操作可通过 JWT 的 `session_id` 对照 `auth.sessions` 检查，普通本地 JWT 校验存在自然到期窗口。
- [Next.js 文件追踪](https://nextjs.org/docs/app/api-reference/config/next-config-js/output) 与 [Sharp 部署要求](https://sharp.pixelplumbing.com/install/)：pnpm monorepo 的原生二进制和动态共享库必须随函数部署，不能只验证开发机可运行。
