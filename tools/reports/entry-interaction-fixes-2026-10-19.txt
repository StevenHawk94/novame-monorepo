页面退出交互 / Surprise Room / Game Room 修复记录
2026-10-19（客户端）

最终实现

1. Retained Tabs 退出交互
- 保持原来的 220ms 视觉转场及滑退时长规则，不添加冷却时间。
- 原来依赖 JS transitionEnd + React commit 才开放目的页按钮。
- 现在目的页提前具备接收触摸能力，但退场中仍由全屏透明原生触摸遮罩保护。
- 遮罩通过同一原生 Animated.Value 的插值，在退场终点移出屏幕；无需等 JS 回调。
- 移出页自身的子按钮不可点击；滑退取消不会提前开放下层。
- 新导航会废弃旧滑退完成回调，包括立即重新打开同一个 route key。
- 保留既有稳定 AnimatedProps 图、Home 几何、兔子动画暂停/恢复策略。

2. Surprise Room
- 新增独立音频资源组件生命周期，仍使用 Expo 官方音频 hooks。
- 选择相框首屏不创建播放器/录音器、不轮询录音状态、不配置系统音频模式。
- 到录音阶段才挂载录音资源；有播放源时才创建播放器。
- 已准备好的接收音频直接借用原播放器，不再创建多余的 null-source 播放器。
- 退出时先停止录音、恢复音频模式，再归还音乐焦点；晚到操作仍有身份/页面校验。
- 阶段资源分离不改变价格确认、不可变发送 key、草稿、失败重试和播放后才标记已读的规则。
- 相框列表改为三列虚拟化列表：首批三行（九张），之后每批两行，现有比例/位置/颜色不变。
- 默认/自定义合成预览不再在选框入口重复执行，只在需要时准备，并让出导航帧。
- 增加 Surprise 路由模块的空闲预解析；不提前挂载摄像头/录音或请求权限。

3. Game Room（遵守“不变慢才采用”）
- 最近缓存直接复用；不再每次 focus 无条件请求 overview + 完整 bootstrap。
- overview 按关系范围校验 TTL：进行中的游戏 30s，普通目录 120s；仅用于后台兜底。
- 私有实时失效仍立即刷新、合并请求期间的事件仍保留一次尾读，不以 TTL 延后通知。
- 可见范围所需的商品图片提前解码，不只准备最上面的两个分类。
- 目录页只让原生导航负责整页退出，移除无实际视觉运动却保留整份列表绘制 300ms 的内部退出注册。
- 答题、结果、规则、权限、购买确认与失败恢复，以及真正的内部阶段转场均保持不变。
- 仍保留原来首批两个分类和屏幕外列表虚拟化。

明确撤回的实验
- 直接增加首批分类、整页预挂载、返回后重建 Game Room 原生视图，都在连续操作中出现更高绘制压力。
- 将重建延到 1400ms 仍不能稳定保证收益，因此没有保留该整页预挂载方案。
- 不用更高的首次绘制成本来强行实现所有分类同帧出现；冷入口仍优先快速打开。

边界
- 模拟器的“首个 UI 帧回调”不是硬件呈现时间，也不是无慢帧保证；多轮结果有系统负载波动。
- 不把不同缓存/预挂载条件的对照数据包装成精确提速百分比。
- Android 模拟器未启动；真实配对账号的双端联测仍由用户登录后执行。
